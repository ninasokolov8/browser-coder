# Shareable web previews, and what Run does for a web file

This replaces four top-level READMEs - `SHAREABLE_PREVIEW_README.md`,
`SHORT_PREVIEW_README.md`, `STATELESS_PREVIEW_README.md` and `CSS_RUN_README.md` - which
between them described three different designs, two of which no longer exist. Nothing
referenced any of them, so there was no way to tell which was current except by reading
the server.

The state below is checked against `server/http/routes/previews.mjs`,
`server/previews/store.mjs` and `server/config.mjs`.

## What a preview is

An HTML page a student can publish and send to somebody. It has to work for a person
who has no account, on a phone, a week later - so it is a real URL serving real files,
not a link back into the IDE.

```
POST /api/previews        publish an immutable project, returns its id
GET  /preview/:id         the wrapper document - never contains student code
GET  /preview/:id/*       the student's own files
```

Ids are 16 random bytes, base64url - 128 bits, so guessing one is not a thing that
happens. Each publish creates a **new** preview; nothing is ever overwritten, so a link
that was sent to somebody keeps showing what was sent.

## The split between the two GET routes is the security boundary

The wrapper at `/preview/:id` is generated by this project and contains nothing the
student wrote. Everything they wrote is served by `/preview/:id/*`, which stamps a
`sandbox` CSP directive **on the response itself** rather than only on the iframe that
embeds it.

That distinction is the whole point (V-03). A sandbox attribute on an iframe protects
the page doing the framing; it does nothing if somebody opens the file URL directly. The
response header travels with the file, so a student's JavaScript is contained whether it
is framed or navigated to.

## Configuration

| Variable | Default | Notes |
| --- | --- | --- |
| `PREVIEW_STORAGE_DIR` | `<tmp>/browser-coder-previews` | **Must be shared persistent storage when running more than one replica.** |
| `PREVIEW_MAX_BYTES` | 5 MiB | Per published project. |
| `PREVIEW_TTL_MS` | 30 days | |
| `PREVIEW_CLEANUP_INTERVAL_MS` | 1 hour | |

The storage directory is the one that matters. A container-local temporary directory
gives every replica its own set of previews, so a link published through one and opened
through another answers "Preview not found" - intermittently, in proportion to the
replica count, which is the hardest possible shape of bug to report.

## Two designs that are gone, and why

**The stateless fragment URL** (`/api/preview#v1.<id>.<codec>.<compressed-site>`) put the
whole compressed site in the URL fragment, so no server needed to hold anything. It
solved the multi-replica problem completely and was removed anyway: the URLs were
enormous, and a link that a chat client truncates is a link that does not work. The
route is gone and no longer accepted, so nothing can generate one.

`STATELESS_PREVIEW_README.md` described this design as current long after it was
removed. That is the reason this file exists.

**Single-file HTML publishing** preceded the project publish. It could not carry a
stylesheet or an image, which is most of what a beginner's first web page is.

## Run, for a web file

A web file is not sent to `/api/run` at all - there is nothing to execute server-side.
Run publishes and opens a preview instead.

**HTML** publishes that page along with everything it references.

**CSS** cannot run on its own, and the IDE says which of the three situations it is in
rather than failing:

- exactly one HTML file links the stylesheet → that page is published and opened;
- no HTML file links it → the IDE explains that a stylesheet is not a program;
- several link it → the IDE lists them and asks which one was meant.

The third case is the reason this is not just "find the first HTML file". Guessing
produces a preview of a page the student was not working on, which looks like the
stylesheet is broken.

The live preview resolves local references the same way a browser would:
`<link rel="stylesheet">`, `@import "…"`, `@import url(…)`, and `url(…)` assets.
